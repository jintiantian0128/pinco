# 当OpenAI一天走了三个高管，而Anthropic发布了一个"杀死Figma"的产品

**——2026年4月19日，AI产品经理深度周报 V9**

> 本文基于2026年4月17-19日硅谷公开信息整理。涵盖OpenAI三高管同日离职与Sora关停倒计时、Claude Design发布与全栈产品化战略、"Product Engineer"新角色崛起、Qwen 3.6开源MoE架构突破、Anthropic估值$8000亿的商业逻辑、以及AI PM角色重新定义等核心事件。

---

## 一、本期核心论点：AI公司的竞争，已经从"模型之战"升级为"产品组合之战"

过去48小时发生了两件事，放在一起看意味深长：

**4月17日，OpenAI三名高管同日离职**——前CPO Kevin Weil、Sora负责人Bill Peebles、企业CTO Srinivas Narayanan。Sora将于4月26日正式关停，Disney的10亿美元投资合作也随之告吹。

**同一天，Anthropic发布Claude Design**——一个让用户通过对话生成设计稿、原型、PPT、营销素材的全新产品。VentureBeat的标题直接写的是"挑战Figma"。

一个在砍产品线、走高管；另一个在扩产品线、招人才。两家公司的战略方向正在急速分化。

**对AI PM的核心启示**：2026年的AI竞争已经不是"谁的模型更强"的单维度较量，而是**"谁的产品组合更合理、更互相增强"**的系统级竞争。模型只是底座，上面的产品矩阵才是真正的战场。

## 二、OpenAI"大出血"：三高管同日离职的深层逻辑

### 2.1 谁走了？

| 姓名 | 职位 | 背景 | 离职原因 |
|------|------|------|---------|
| **Kevin Weil** | 前CPO，后转任OpenAI for Science负责人 | Instagram前产品副总裁 | 团队被解散、去中心化到其他研究组 |
| **Bill Peebles** | Sora负责人 | 领导OpenAI短视频AI产品线 | Sora 4月26日正式关停 |
| **Srinivas Narayanan** | 企业应用CTO | B2B Applications负责人 | 公司战略重心调整 |

此外，Stargate数据中心项目也有三名核心负责人（Peter Hoeschele、Shamez Hemani、Anuj Saharan）已离职或即将离职。

### 2.2 "砍掉side quests"的战略意图

OpenAI正在执行一次激进的战略聚焦：

1. **关停Sora**（4月26日应用关停，9月24日API关停）——从创意工具赛道撤退
2. **解散OpenAI for Science团队**——从独立科学研究赛道收缩
3. **聚焦Codex超级应用 + GPT垂直模型**——集中资源打企业市场

The Decoder的分析精准："这标志着OpenAI从创意AI工具向编码和企业产品的重大战略转向。"

### 2.3 PM视角：Sora之死的产品教训

Sora的失败值得每个AI PM深思：

- **时机问题**：推出仅6个月就关停，Disney签约才3个月就毁约
- **定位问题**：在AI视频还没有清晰PMF的时候强推消费者产品
- **资源问题**：同时运营ChatGPT、Codex、Atlas、Sora、GPT Store……产品线过度分散
- **竞争问题**：AI视频赛道被Runway、Pika、可灵等迅速追赶，差异化不足

**教训**：AI PM必须有"杀产品"的勇气。在资源有限的情况下，不是"做更多"，而是**"做更少但更深"**。

## 三、Claude Design：Anthropic从"AI实验室"变成"全栈产品公司"

### 3.1 产品全貌

4月17日发布的Claude Design是Anthropic Labs旗下的第二个独立产品（第一个是Claude Code）：

**核心能力**：
- 基于Opus 4.7的视觉能力，通过对话创建设计稿、交互原型、PPT、one-pager、营销素材
- 支持**内联评论、直接编辑文本、自定义调节滑块**进行精细控制
- **自动导入团队设计系统**（读取代码库和设计文件，自动应用品牌色、字体、组件）
- **Web Capture**：直接抓取网站元素，原型看起来像真正的产品
- **一键交接Claude Code**：设计完成后打包成handoff bundle，直接传给Claude Code实现

**导出选项**：内部URL分享、Canva、PDF、PPTX、独立HTML

**定价**：包含在Pro/Max/Team/Enterprise订阅中，不额外收费

### 3.2 客户验证

| 公司 | 角色 | 评价 |
|------|------|------|
| **Canva** (CEO Melanie Perkins) | 合作伙伴 | "把想法和草稿从Claude Design带入Canva，立即成为可编辑的协作设计" |
| **Brilliant** (高级产品设计师Olivia Xu) | 早期用户 | "最复杂的页面在其他工具需要20+提示词，Claude Design只需2个" |
| **Datadog** (PM Aneesh Kethini) | 早期用户 | "以前一周的来回评审，现在在一次对话中完成" |

### 3.3 Anthropic的产品矩阵分析

现在来看Anthropic的完整产品组合：

```
Claude.ai（对话入口）
├── Claude Code（代码生成/推理）  
├── Claude Design（设计/原型）     ← NEW
├── Claude Cowork（桌面自动化）
├── Claude for Chrome/Slack/Excel/Word/PowerPoint（分发渠道）
└── Skills（用户自定义能力扩展）
    
底座：Mythos / Opus / Sonnet / Haiku（四层模型矩阵）
```

**关键洞察**：Anthropic正在构建一个**"从想法到交付"的闭环**——用Claude对话产生想法，用Claude Design出设计稿，用Claude Code写代码，用Claude Cowork完成桌面操作。全程不离开Claude生态。

VentureBeat说的对：这不是在做一个"设计工具"，这是Anthropic从AI实验室向**全栈产品公司**的战略转型信号。

## 四、"Product Engineer"：AI时代PM角色的重新定义

### 4.1 来自Anthropic增长负责人的预言

Anthropic增长负责人Amol Avasare（前MasterClass PM）在Lenny's Podcast上的发言引发了硅谷关于PM角色的最新辩论：

**核心数据**：
- 工程师借助Claude Code等工具，生产力提升**2-3倍**
- 团队人数不变，意味着PM和设计师现在支撑的"等效工程产出"大幅增加
- **"PM和设计被挤压了"**

**Anthropic的内部实验**：
- 如果一个项目需要**两周以内**的工程时间，工程师直接担任PM角色
- 工程师负责与法务沟通、与跨职能利益相关方协作
- Avasare称之为**"把工程师deputize为mini PM"**

### 4.2 "Product Engineer"角色定义

HumanX大会上Zencoder CEO Andrew Filev的定义：**Product Engineer = PM + 软件工程师的混合角色**。

特征：
- 既能理解用户需求和商业逻辑
- 又能直接用AI工具（vibe coding）快速实现
- 在AI加速开发的背景下，PM的"翻译"功能被压缩，直接"做"的功能更被需要

### 4.3 对AI PM的冲击分析

**不会消失，但会分化的角色**：

| 类型 | 变化方向 | 关键能力 |
|------|---------|---------|
| **战略型PM** | 更被需要 | 产品组合决策、生态位判断、利益相关方管理 |
| **执行型PM** | 被压缩 | 传统需求文档、项目跟踪正在被AI工具替代 |
| **技术型PM** | 向Product Engineer演化 | 能用AI工具直接出原型、写代码的PM更有竞争力 |
| **行业型PM** | 价值飙升 | GPT-Rosalind模式下，懂行业的PM是稀缺资源 |

**Avasare的关键判断**：Anthropic自己也在**招更多PM**来弥补AI提效后的管理缺口。所以不是PM消亡，而是PM的职责在重新分配。

## 五、Qwen 3.6-35B-A3B：35亿参数做到了350亿参数的事

### 5.1 架构创新

4月16日，Alibaba Qwen团队开源了Qwen3.6-35B-A3B：

| 维度 | 参数 |
|------|------|
| 总参数量 | 35B |
| 每token激活参数 | **3B**（仅8.6%） |
| 架构 | Sparse MoE（稀疏混合专家） |
| 授权 | Apache 2.0（完全开放） |
| 上下文 | 1M tokens |

**关键成就**：在编码基准测试中，3B激活参数的Qwen3.6击败了多个10倍以上参数量的dense模型。

### 5.2 "认知密度"范式的极致演绎

回顾过去两周的"认知密度"主题：

- **Anthropic Advisor**：小模型执行 + 大模型顾问（成本降80%）
- **Opus 4.7 xhigh**：半价token预算超旧版全价效果
- **Qwen3.6 MoE**：35B参数只激活3B，效果碾压dense 30B+模型

三个独立事件指向同一个结论：**AI行业的竞争维度正在从"参数量"转向"每激活参数的智能密度"**。

对PM的直接影响：你选择模型时不能只看"参数多大"或"基准多高"，要看**"同等效果下成本最低的部署方案"**。Qwen3.6的3B激活就够用的场景，你用200B的模型就是在浪费钱。

### 5.3 Qwen 3.6-Plus（闭源版本）

Alibaba于4月2日发布了Qwen3.6-Plus，与开源版不同的是：
- **闭源**，仅通过阿里云和Qwen Chat访问
- 1M token上下文窗口
- 兼容Claude Code、OpenClaw、Cline等第三方编码工具
- 支持图像、文档、视频分析

**开源+闭源双轨并行**：Alibaba的策略是用开源建生态（3.6-35B-A3B），用闭源赚收入（3.6-Plus）。这和Meta的Llama策略如出一辙。

## 六、OpenAI vs Anthropic：产品战略的"加法"与"减法"

本周最具战略意义的对比：

| 维度 | OpenAI（减法） | Anthropic（加法） |
|------|--------------|----------------|
| 产品动作 | 关停Sora、解散Science团队 | 发布Claude Design、Opus 4.7升级 |
| 人才流向 | 三高管+Stargate三核心离职 | 正在招更多PM |
| 模型策略 | 垂直专用（Cyber、Rosalind） | 通用提升（Opus全面碾压） |
| 商业模式 | 广告+订阅双轨 | 纯订阅/API |
| 估值信号 | IPO准备中 | $8000亿要约被拒绝 |
| 政治关系 | 与白宫紧密但争议不断 | 从被禁到被约见，关系修复中 |
| 战略聚焦 | Codex超级应用 | Claude全栈闭环 |

**核心区别**：

OpenAI选择了**"做减法后聚焦超级应用"**——砍掉Sora、收缩Science，所有资源押注Codex + 企业市场。这是一个赌"单一入口通吃"的战略。

Anthropic选择了**"做加法构建产品矩阵"**——Code、Design、Cowork、Chrome/Office插件……每个产品覆盖工作流的一个环节，形成闭环。这是一个赌"生态锁定"的战略。

**PM判断**：两种战略都有道理，关键在执行。OpenAI的风险是超级应用做不出来就什么都没有；Anthropic的风险是产品线太多导致每个都做不深。

## 七、Sora之死与Claude Design之生：AI产品"PMF信号"的识别框架

将Sora（失败产品）和Claude Design（新发布产品）的PMF信号做对比分析：

| PMF信号维度 | Sora（失败） | Claude Design（待验证） |
|------------|-----------|---------------------|
| **用户需求明确性** | ❌ "AI生成视频"需求模糊，创作者和消费者定位不清 | ✅ "对话生成设计稿/原型"需求明确，PM/设计师/创始人都能用 |
| **工作流嵌入度** | ❌ 独立应用，不融入现有工作流 | ✅ 与Claude Code直接打通，导出到Canva/PPTX/HTML |
| **替代方案清晰度** | ❌ 替代什么？YouTube？TikTok？不清楚 | ✅ 替代Figma的早期探索阶段 + PPT制作 |
| **付费意愿信号** | ❌ Disney合作3个月就毁约 | ✅ 包含在现有订阅中，降低试用门槛 |
| **复购/留存逻辑** | ❌ 一次性生成，缺乏持续使用场景 | ✅ 团队设计系统沉淀后，迁移成本递增 |
| **AI优势可持续性** | ❌ Runway/Pika/可灵快速追赶 | ⚠️ 如果Figma加入AI能力，护城河待验证 |

**PM框架提炼——AI产品的"PMF五问"**：

1. **用户能否一句话说清楚它替代了什么？** （如果不能，PMF不存在）
2. **它是否嵌入现有工作流而非创建新工作流？** （嵌入=低摩擦采用）
3. **用得越久是否越难离开？** （数据/习惯/系统沉淀=留存）
4. **AI能力差异化是否可持续？** （如果3个月后竞品追平，不是壁垒）
5. **商业模式是否与使用行为对齐？** （按需生成≠订阅，按工作流=订阅）

## 八、本期框架："产品组合竞争力"评估模型

综合本周观察，提出AI PM可直接使用的**"产品组合竞争力"五维评估模型**：

| 维度 | 评估问题 | Anthropic | OpenAI |
|------|---------|-----------|--------|
| **闭环完整度** | 用户能否在你的生态内完成全流程？ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |
| **产品间协同度** | 各产品是否互相增强？ | ⭐⭐⭐⭐⭐ (Design→Code→Cowork) | ⭐⭐⭐ (Codex正在整合) |
| **模型-产品适配度** | 模型能力是否精准匹配产品场景？ | ⭐⭐⭐⭐ (Opus 4.7视觉→Design) | ⭐⭐⭐⭐ (Rosalind→生命科学) |
| **迁移成本递增性** | 用得越久越难走？ | ⭐⭐⭐⭐ (设计系统沉淀) | ⭐⭐⭐ (插件生态) |
| **资源聚焦度** | 是否有清晰的取舍？ | ⭐⭐⭐ (产品线在扩张) | ⭐⭐⭐⭐ (主动砍产品线) |

**总分**：Anthropic在闭环和协同上领先，OpenAI在聚焦和垂直适配上有优势。谁赢取决于**执行速度**——Anthropic能否把产品矩阵做深，OpenAI能否把超级应用做出来。
