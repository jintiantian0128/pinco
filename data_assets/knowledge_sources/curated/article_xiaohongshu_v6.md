## 💡 第一弹：Advisor Strategy——2026年最被低估的Agent架构创新

4月9日Anthropic悄悄发了个东西，没上头条，但它可能比Mythos对PM更重要。

**叫Advisor Strategy（顾问策略）。一句话解释：**

> 让便宜的小模型干活，遇到难题时问一下贵的大模型，大模型给个建议就走。

**传统做法 vs 新做法：**

| | 传统做法 | Advisor Strategy |
|---|---------|-----------------|
| 🧠 谁指挥？ | 贵的大模型（Opus）做老板 | 便宜的小模型（Sonnet/Haiku）做主角 |
| 💰 谁花钱多？ | 大模型处理一切 = 贵 | 大模型只回答400-700字 = 省 |
| 🔧 实现难度 | 自己搭编排逻辑 | API加一行配置就行 |

**硬数据：**

| 配置 | 性能 | 成本 |
|------|------|------|
| Sonnet单独 | 72.1% | 基准 |
| Sonnet + Opus顾问 | 74.8%（+2.7%） | 省11.9% |
| Haiku单独 | 19.7% | 基准 |
| Haiku + Opus顾问 | 41.2%（翻倍！） | 远低于Opus直接跑 |

法律科技公司Eve Legal实测：Haiku + Opus顾问 = 前沿模型质量，**成本只有1/5**。

**为什么这对PM特别重要？**

因为它改变了你做模型选型的方式：

- ❌ 旧问题："我们用Opus还是Sonnet？"
- ✅ 新问题："任务中哪5%需要顶级推理？其余95%用便宜的就行？"

**职场提效点💡**：今天就去试。在你的Claude API调用中加一个advisor工具，executor用Sonnet，advisor用Opus，max_uses设3。一行代码改变，成本可能降一半以上。

## 🔥 第四弹：OpenClaw事件——当你的平台和第三方打起来

**全事件链：**
- Peter Steinberger的OpenClaw是GitHub增长最快的开源Agent框架之一
- Anthropic调价，要求OpenClaw用户通过Claude API按量付费（被称为"claw tax"）
- Steinberger遵守了新规则，但账号还是被暂停了
- 收到邮件："内部调查发现可疑信号，违反使用政策"
- 数小时后Anthropic工程师回应："我们不会因OpenClaw使用ban人"，恢复访问

**暴露了什么？**

Anthropic同时卖Claude API（给第三方Agent用）和Cowork（自己的Agent产品）。当OpenClaw太成功时——

> 它既是API收入来源，又是Cowork的竞争对手。

这就是经典的**"平台裁判员困境"**。你既当运动员又当裁判，开发者会质疑每一次政策变更的动机。

**职场提效点💡**：如果你在做平台型AI产品，Day 1就必须设计：(1) API政策变更的提前通知机制 (2) 争议解决的透明流程 (3) 自有产品与第三方竞争时的利益冲突披露。一次"误ban"就能摧毁整个开发者社区的信任。

## 🎯 今日一页纸总结：Agent架构选型三问

下次做Agent架构决策时，问自己三个问题：

```
❓ 问题1：任务智能密度是什么分布？
   → 均匀高密度 → Opus直接跑
   → 尖峰型（95%机械+5%关键）→ Advisor Strategy
   → 均匀低密度 → Haiku/Sonnet直接跑

❓ 问题2：能力风险等级多高？
   → L1低风险（文本生成）→ 开放访问
   → L2中风险（代码/数据）→ 身份验证
   → L3高风险（安全扫描）→ TAC式分级
   → L4极高风险（零日发现）→ Glasswing式受控联盟

❓ 问题3：平台策略是什么？
   → 自建 → 最大控制，最高成本
   → Managed Agents → 快速上线，供应商锁定
   → Agent Framework → 企业级，需自建运行时
   → MCP+A2A原生 → 最灵活，生态仍在演进
```

**记住Advisor Strategy的核心洞察：任务中的智能需求是非均匀分布的。为5%的需求付100%的成本，是2026年最常见的AI产品浪费。**
